## Evidencia y límites de aceptación

- Servidor: suite completa en PostgreSQL/Redis; regresión específica de reportes después de ajustar la plantilla. Web: pruebas de componentes/ViewModel, build y navegación real. Android: repositorios Kotlin por HTTP real y pruebas de Compose/dispositivo, diferenciadas de las pruebas con respuestas controladas.
- Casos de borde: periodos diferentes, notas nulas, planes Free/Pro/revocados, propiedad de trabajos/etiquetas, reintento idempotente, conflictos 409, recarga y descarga con firma/longitud/hash. La falta de espacio se simula con un escritor que devuelve ENOSPC; no se llena el almacenamiento del usuario.
- Los ensayos con tiempos corresponden a esta laptop y a la red local. No acreditan un tiempo universal en otro teléfono o servidor.
- Se conservan como pendientes de aceptación del equipo: revisión formal de metodología y pesos académicos; prueba en el teléfono físico y versiones de Android elegidas para la entrega; validación conjunta final del guion. Son actividades de aceptación, no servicios o pantallas faltantes.
- La ampliación de datos a las 503 empresas, la actualización diaria y la contratación/cobro de Pro no forman parte de este cierre. Los faltantes financieros se muestran como ausentes.
